# The small CAD bench

Commands a session calls over files in its working directory, each answering in plain text and numbers, for the local model's first project (M18 in mqucifer/project-print `ROADMAP.md`, ADR 0010 there, and mqucifer/print-shop#14). A trial on 2026-11-01 showed tools reporting success when they were wrong, so **every answer gets a second check by a different method**, and the bench says when the two differ. It never touches the printer, and it holds no model call. Motion, balance, stiffness and strain come as their own issues when a project's number fails without them.

```
scripts/bench.py build                       # once: the one image, if the disk has room
scripts/bench.py check                       # the image and the disk against their limits
scripts/bench.py clearance a.step b.step     # any command below, over the current directory
scripts/bench.py python script.py            # your own script, in the same container
```

[The rounds](rounds.md) use it as a session's tool. A session inside the image can call the same commands directly, by mounting `src/print_shop/bench` read-only (`host.py` shows how). Nothing fences the model off: these are tools it may use, and it can write its own scripts.

## What comes back

The first line is the verdict. Then come the numbers, each with how it was read, then at least one `second check:` line, and last `saved:`, naming the text and JSON files written under `bench-out/`. Every figure a report may cite is in those files, and each says how it ran: the image's id, the code's commit, and the CPU, memory and network limits as the container read them.

| Exit | Verdicts | It means |
|---|---|---|
| 0 | `OK`, `CLEAR`, `TOUCHING` | both methods agree, and nothing's wrong |
| 1 | `FAIL`, `INTERFERE`, `TOO CLOSE`, `TOO LOOSE`, `NO CHANGE`, `PARTIAL` | both methods agree that something's wrong |
| 2 | `DISAGREE`, `NO ANSWER` | there's no answer to rely on: read the numbers, and don't pick one |
| 3 | | the command itself was wrong |

An answer with no second check behind it becomes `NO ANSWER`, whatever it first said.

## The commands

| Command | Answers | First method | Second method |
|---|---|---|---|
| `info FILE` | size, volume, bodies, flat heights, the file's size and its flat faces under 1 mm across | the mesh; OCCT's oriented box round each flat face | OCCT's volume on a STEP; sections stacked on an STL; each flat face's width by points along its edges |
| `clearance FILE... [--min-gap G] [--max-gap G2] [--lift D [--along A]] [--box NAME=X0,Y0,Z0,X1,Y1,Z1]... [--facing NAME=DIR]...` | overlap and gap, every pair, across files or a file's solids, a gap range for parts meant to mate, the last file lifted off its seat first, and each pair's least gap at each place named | Manifold on a fine mesh for the overlap; the gap by OCCT's exact distance on a STEP, the mesh's on an STL | OCCT `common` and `cut`, and the mesh's gap, on a STEP; sections clipped by Shapely and sampled points on an STL |
| `readback BEFORE AFTER [--cutter C] [--expect-delta V] [--min-share S]` | volume before and after, and how much of a cutter was in the body | the mesh | OCCT, or stacked sections |
| `rays FILE --centre X,Y,Z [--axis A] [--d D] [--depth H]` | a cut feature measured from its axis: rays that hit nothing, the distance across, the nearest wall, the wall beyond, the floor, and from a point in air, what `across` measures | rays on the mesh | a plane section, with a circle fit |
| `panes FRAME --pocket-z Z [--lip-z Z] --clearance C [--pane-thickness T]` | a pane from each opening, written to `panes/FRAME/`, its fit, and the edge with no lip | polygons on the section | the pane as a solid against the frame's walls over the pocket's height, and rays up from the edge |
| `capture FRAME --pocket-z Z --clearance C --pane-thickness T [--pane-floor-z F] [--min-lip M] [--layer L] [--panes N]` | whether each pane is held by shape on both faces, wherever its play lets it sit: the lip, how thick, where it's thin, and whether it can slide or swing out | sections stacked beyond the pocket, read as polygons | rays beside the pane's edge, and the pane as a solid swept out of the frame |
| `thin FILE [--nozzle N] [--layer L] [--min-body V] [--one-body]` | features under the nozzle's width, floors under a layer, and tiny pieces | sections opened by the nozzle | rays across each spot, level rays through the walls and straight rays through level floors, and OCCT's count of solids |
| `pause FRAME --pocket-z Z --pane-thickness T [--layer L] [--first-layer F] [--max-gap G] [--min-room R]` | the layer to pause after, and the room over the pane | sections layer by layer | the flat faces' heights |
| `wall FILE --hole X,Y,Z [--axis A] [--min-wall W]` | the least wall round one hole, along its whole length, and toward what: the part's outside or another opening | sections across the hole, a layer apart, as polygons | rays out to the hole's wall, then through it along the wall's normal |
| `render FILE... [--views ...] [--section Z...] [--close X,Y,Z,R[,VIEW]]... [--cut AXIS=AT[,AXIS=FROM:TO]]... [--look FILE=COLOUR[:LABEL]]... [--test-piece FILE]...`, or `render --variant NAME=FILE[,FILE...]... [--close ...]... [--cut ...]... [--look ...]... [--test-piece FILE]...` | pictures from the standard views, and a sheet of them, or a sheet with a labelled row for each variant, each file in its colour, marked by its name, and named in a legend. A close-up is R mm all round a point. A cut is every file cut by one plane | VTK, offscreen | the mesh projected by arithmetic against the painted outline, each close-up's triangles projected and filled against its pixels, the section's area against its pixels, and each file's area on a cut by the mesh against OCCT's section |
| `params SCRIPT --set NAME=VALUE [--max-left N] [--keep DIR]` | which dimensions, volumes and pieces moved when one parameter changed | each piece's figures, three runs | the meshes' symmetric difference, and a run with nothing changed as the control |
| `light FRAME PANE... [--with FILE]... [--min-open P]` | the share of each pane open straight through the frame, in percent, and the narrowest band of frame a person sees between two open pieces | each pane's footprint less the frame's shadow, the frame cut at every layer and each level face | rays straight up through the frame from a grid in each footprint, and rays along the line across the narrowest band |
| `thickness PANE... [--max T] [--min T]` | each pane's thickness straight through, its thickest and thinnest | the fine mesh's height | rays straight up through the pane from a grid, each reading the material it crosses |
| `layout FILE.json [--inset D]... [--join mitre\|round] [--min-width W]` | a flat layout of named pieces, in 2D: whether each is one piece and where each part is, its least width and where, its sharp tips, what an inset leaves of it and where it cuts it, any two that overlap, and a picture with each piece labelled | rays square to each edge, to the edge facing back | the nearest point facing back, from each point of the edges; the parts by the picture's own pixels |
| `edges FILE... [--with FILE]... [--min-radius R] [--box NAME=X0,Y0,Z0,X1,Y1,Z1]... [--facing NAME=DIR]...` | each outside edge a finger meets: sharp, and how far it turns, or rounded, and the least radius, with where, overall, for each group (upright, top, bottom, side) and for each place named | the exact surface's normals along each edge and its curvature over each rounded face; a 12 mm ball's reach on a grid | the mesh cut square to each sharp edge, and along each rounding where it bends most, with a circle fitted; each ball's centre held clear by the mesh's exact distance |

**Toolsets** (mqucifer/print-shop#37). The Sponsor, 2026-11-03: "not everything is going to be a stained glass print". So a run has the core, and a request's `## Kind` adds its kind's commands. The core is `info`, `clearance`, `readback`, `rays`, `thin`, `wall`, `pause`, `params`, `render` and `layout`. Stained glass adds `capture`, `panes`, `light` and `thickness`, and an enclosure `edges` (mqucifer/print-shop#60). `rounds/toolsets.py` holds the sets, and [the rounds](rounds.md#toolsets) say how a run uses them. From the command line, every command works as before.

**A flat layout, read in 2D** (mqucifer/print-shop#61). On `suncatcher-3`, 12 of the 35 calls that reasoned past 20,000 characters and repeated themselves stalled on which piece or neck an inset makes, and which piece is which, and the model printed bounding boxes to find out. `layout` reads a layout the model's script writes: JSON with `pieces`, each name and its outline as GeoJSON (`shapely.geometry.mapping`) or WKT, in mm (`bench/layout.py`).
- **Each piece:** one piece or not, and each part's area, a point inside it and its box, largest first, so "which is which" is a reading. Two pieces that overlap are named, with how much.
- **Its least width:** straight across, from an edge to the edge facing back within 20°: a waist, a bar, an arm, a ring, a cell side to side. Where the sides run further apart it's a corner or a tip, which an inset moves back and never cuts, so it isn't a width. Rays square to the edge are the reading, and the nearest point facing back the second: across parallel sides the two are the same, and within 20° of parallel the second reads as little as cos 20° of the first, never more. Further apart than that, and the points' spacing (at most 0.05 mm), is `DISAGREE`.
- **Sharp tips:** a corner sharper than 75°, read from the outline's own points, with where and its angle. It narrows to nothing, so it's under any `--min-width`.
- **An inset of D** (`--inset`, mitred as a layout's pockets are, or `--join round` for the true distance): its parts, its least width, and where it cuts the piece in two or takes an arm away, each stretch of the piece narrower than 2D by its narrowest and how far it runs. A negative D is an outset.
- **The picture** comes to the model, as `render`'s does: each piece in its colour, labelled on each part, its least width in red, its tips ringed, each inset's outline in black.
- `--min-width W` fails a piece narrower than W, or with a sharp tip, saying where. Without it the answer is `OK` with its readings. It reads a layout, not the part, so no need names it.
- **Back-tested** on planted pieces with arithmetic answers (`test_a_layout_says_each_piece...`), and on layouts made from scratch, up to 61 pieces with two insets in 30 s (`~/print-shop/proofs/m18-lacked/`). The reading went through three first methods before this one, each caught by the second: chords at up to 37° from square read an arm's round end at 0.8 of its width, the widest disc that fits read a wedge's rounded tip by its cap, and Delaunay edges miss the nearest point across a cell with no two sides parallel.

**Light and pane thickness** are the stained-glass toolset's readings of what a person sees (`bench/glass.py`). In all three stained-glass runs light through each pane was measured by hand, outside the bench, and on two a floor went under the panes. `light` reads it along z, as the piece hangs flat to the light: a floor under a pane reads 0%, and a wide lip on a small cell reads low. The grid's band is a quarter of its spacing along every edge it crosses, as a straight edge between grid points misclassifies that much on average, and at worst all one way. `thickness` reads each pane's height, and rays through it, so a pane thicker in one place reads both. **Neither has a default limit:** a limit is the request's, `--min-open` or `--max` and `--min`, and with none each is a reading that passes and says so. How much light PETG lets through at a thickness isn't the bench's.

`params` reads a number assigned once at the top level of a design's script (`BaseCircle = 20.0`), and runs the script in a scratch folder, so the design isn't touched. A parameter that moves nothing is `NO CHANGE`. On a Fusion copy, changing `BaseCircle` left the outer ring and motif in place while Fusion reported everything healthy (mqucifer/print-shop#15): this names each piece that moved and each that didn't. One that leaves pieces behind is `PARTIAL`, and `--max-left N` says how many may stay and still read `OK`. `--keep DIR` copies what the changed run wrote into a new folder, under the same names: the refinement pass checks a proposed change to a part on those files ([the rounds](rounds.md#the-refinement-pass)).

**Checks hold what a need says** (mqucifer/print-shop#24). Each of these can now say what a need says, and fails otherwise:

| A need's words | What used to pass | Now |
|---|---|---|
| A margin over a pane | No room at all: `--max-gap` is only a ceiling | `pause --min-room R`, and `least_room_over_pane_mm` is a number a need can limit |
| One connected solid | Several bodies | `thin --one-body` |
| Moves every piece | One piece moved of several | `params` is `PARTIAL` when pieces stay behind |
| So many panes | Fewer panes read than files | `capture --panes N` |

No command can tell what a need means, so these are asked for. With nothing asked, they read as they did, except `params`.

**A sheet shows what it asks about** (mqucifer/print-shop#26). On `cup-1` the renderer gave each file a colour from a list of 5, starting again at the 6th, so a pane was drawn in the frame's colour and didn't show as glass, nothing on a sheet said which colour was which file, and the model described the design it meant, not the picture.
- **`--look FILE=COLOUR[:LABEL]`** draws a file in its colour, a name (`blue`, `amber`, `clear`, perhaps `light` or `dark`) or `#rrggbb`, from `bench/colours.py`, which the harness reads too. A file with none takes the colour furthest from every other on the sheet. Each file is marked where it is on every picture, after the picture's check, by its name since mqucifer/print-shop#54 (below), and the legend under the sheet names each file, its label and its colour. `drawn:` lines say the same in text, and `numbers.files` in the record.
- **What each view shows** is counted: each view is drawn again unlit, one exact colour a file, and `numbers.seen_px` has each file's pixels. A file no view shows is said, "not seen in any view drawn", as on `cup-1`, where a pane's colour hid it.
- **`--cut`** is a view: every file cut by one plane, each in its colour, the largest first so what sits in an opening, such as an island of frame in a pane's hole, is drawn over it. `z=3` is level; `x=50` is upright, seen from +x; `y=40` from the front; and `x=50,y=20:40` draws only that stretch, so a frame 6 mm tall is more than a line and a pane can be judged in its pocket. Each file's area is checked against OCCT's section of its exact surface, and the painted area against the polygons. Two files whose sections overlap are said, by how much, which no other picture shows. A cut is a column beside the views and close-ups, in plain and variant sheets.

**An island of frame inside an opening** (mqucifer/print-shop#27). On `cup-1` one pane had holes cut in it for others, so the frame's walls round those holes stood inside its opening, joined to the rest only through the lips above and below. Every command read that opening as one solid pane, and nothing said so: `capture` read the island's volume as a pane "too thick for its pocket", `pause` read it as a ceiling mid-pocket, and `render --section` drew the opening over it. Now an opening is the hole less any island inside it, so its pane has a hole round each, and:
- `capture`, `pause`, `panes` and `render --section` read it, and say "opening N has 1 island(s) of frame inside it". `capture` reads the lip round each hole of a pane as it does the outer edge, ring by ring.
- An island closer to the opening's edge than twice the play can't have pane between: the pane goes round it open, and `capture` says so with where. One a pane can't go round at all is named, with the opening's centre and size, and not read.
- `pause` reads what each layer leaves free of the whole opening, not the hole round one point of it, which could stand on an island.
- A section is drawn piece by piece, so an island shows. Its line counts the pieces and islands, and one that fails its own area check names each piece it didn't draw.
- `panes` writes a pane with holes as a STEP too, checked by its volume.

**`capture` says where each pane is.** Its numbers are its own, largest opening first, and the model read its "pane 1" as `pane_1.step` for 33 calls. Each pane is now said with its centre, its size, its holes and, where a file beside the frame has its outline, that file: the outlines' sections at the pocket's height share 90%, and OCCT finds a point inside the bench's pane inside the file's solid. Two files lying in one opening with no wall between are named. A pane that meets the frame where it sits says whether that's the ceiling (too thick), the floor (set too low), or frame standing in its place, with where.

**A curve stored as flat strips** (mqucifer/print-shop#54). 121 of the 226 STEP files in approved folders stored every curve as flat faces, one for each segment of a Shapely polygon extruded with `polyline`: 360 MB, against 7.9 MB for the other 105. `info` now reads `file_kb`, `flat_faces` and `small_flat_faces`, the flat faces under 1 mm across their plane, by OCCT's oriented box round each and again by the least rectangle round points along its edges. It's a reading, never a failure: a part with no curves can have small flat faces. With any, it says that a curve may be stored as strips, and names the skill that builds it as a curve. On an 80 mm ring 3 mm thick, built from polygons of 96 segments a quarter, it reads 768 of 770 flat faces and 2,989 kB; as two circles, 0 of 2 and 9.3 kB. An STL has no faces of its own, and says so. **Under 1 mm misses coarse faceting:** at Shapely's default of 16 segments a quarter, that ring's strips are 3 mm tall and 3.4 to 3.9 mm round it, and none reads small, though the ring is 0.048 mm off its circle. The skills say what that costs.

**`capture` with several plays** (mqucifer/print-shop#54). `--clearance` is one play for every pane. On `eval-choice-1` two cells had different plays, and nothing in the reply said so. A pane's own file is the one matched, or, where `--clearance` is so far from its play that none matches, the one file lying in its pocket: nine tenths of it inside, covering half the pocket or more. Its play is read from that file: the room between the pocket and the file's outline at `--pocket-z`, over the length round both, and as the second reading, the median distance from points round the file's edge to the pocket's wall. A pane whose play differs from `--clearance` by more than 0.02 mm, the coarse mesh's chords on both outlines, is named in `plays_differ`, with both readings, and the reply says one run can't judge panes of different plays, and the `--clearance` to run again at. Where every pane's file has the same other play, it says to run again at that. It judges nothing: the verdict is as it was at `--clearance`. On `eval-choice-1`'s approved frame and panes, at the need's 0.25 mm nothing is named; at 0.85, the play the run once gave its small pane, the bench's panes match neither file, and both are named with 0.25 mm by both readings (`~/print-shop/proofs/m18-tools/evals/choice1/`).

**A sheet marks each file by its name** (mqucifer/print-shop#54). The approval sheet numbered files in order, so `pane_1.step` was marked "2" beside the model's own layout, where pane 1 was another. Each file is now marked on every picture by its name less `.step`, `pane_1`, or by its path where two files share a name, and the legend names each file, its label and its colour. Its words wrap within its entry, and nothing is cut: a legend once ended "none was giv". `numbers.files` keeps each file's `number` in order, and its `mark`.

**A height on a level face** is still refused, and the refusal now says the middle of the stretch either side, with how many openings each has.

**A gap range** (mqucifer/print-shop#60). `clearance --min-gap` alone let a lid too loose to stay on pass. `--max-gap G` fails a pair whose least gap is over G, `TOO LOOSE`, exit 1, so parts meant to mate are held from both ends, and a need on a lid's play carries both (`reports.BOTH_ENDS`). A pair that touches has a least gap of 0, never too loose, and a lid seated on its base touches it whatever its lip's play: with `--max-gap`, the reply says so, and to run again with `--lift`. A range the wrong way round is a usage error.

**A mated part's play, read on the printed file** (mqucifer/print-shop#65). The docs said to read a lid's play on a copy lifted off its seat, and `done` refuses a need on a file that isn't printed (mqucifer/print-shop#64): on `eval-lid-1` the model made the copy, `done` refused it, and the lid was saved 2 mm up instead, and on `eval-fit-2` the frame was built round the pane where its file sat. `--lift D` moves the last file named D mm along `--along` (z unless said, D signed) before measuring, and only there: its file stays where it is, and the reply's first line says what moved, by how much, and that every figure is with it moved (`numbers.lift`). The need is then on the printed lid. D must be more than `--min-gap` and `--max-gap`, or it's a usage error, as a lift short of the play would read as the gap. Where a pair's least gap still reads D, it's the faces that seat, so the play is at least D and isn't read: the reply says so. On the tray's lids seated, `--lift 0.5 --min-gap 0.1 --max-gap 0.3` is `CLEAR` at 0.2 mm of play, and `TOO LOOSE` at 0.6, where it reads the lift and says so, as the lifted copies did.

**The gap a verdict reads** (mqucifer/print-shop#65). On `eval-fit-2`, `clearance references/pane_1.step frame.step --min-gap 0.25` read `TOO CLOSE` where OCCT's exact distance was 0.2500 round the pane's curved corners: the verdict read the mesh, 0.24998, as its chords cut into the pocket's concave corner, and the allowance of 2 × 0.002 mm was on `--max-gap` only. The same allowance under `--min-gap` would pass a gap truly short by the chords, so instead the verdict on a STEP pair reads OCCT's exact distance, `gap_mm`, at both ends, to 1e-6 mm, the mesh's being its second check within the chords on both faces, and `DISAGREE` past them. On an STL pair it reads the mesh, which is the file's own surface. A need names `pairs.0.gap_mm`. Planted: a pane 20 × 14 rounded 3 mm in a pocket 0.25 mm wider all round, its corners 3.25: OCCT reads 0.24999999999999853, the mesh 0.2499806; `--min-gap 0.25 --max-gap 0.25` is `CLEAR`, where the old rule was `TOO CLOSE`, and 0.2501 is `TOO CLOSE` (`~/print-shop/proofs/m18-bench/min-gap/`).

**A gap by place** (mqucifer/print-shop#72). A pair's least gap is its tightest face, so a mated pair with two plays reads only the smaller. On `eval-fit-3` a pane sat in its pocket with 0.25 mm of play round its edge, the request's, and 0.15 mm on its faces, the model's to choose so the pause works: `clearance` read 0.15, and the edge's need couldn't be read on the printed part. A section through the pocket was refused at `done`, as a need checks the printed part (mqucifer/print-shop#64), `rays --d` can't hold a rounded rectangle, and a size isn't the play. Five rounds went on it. On `eval-fan-1` the clip arms' side play couldn't be read apart from the seated plate's contact, and lifted, the barb overlapped. Now `clearance` takes places, as `edges` does:
- **`--box NAME=X0,Y0,Z0,X1,Y1,Z1`** reads, for each pair, the least gap between the parts' surfaces inside the box, on the files where they lie. Put it round the faces whose play it is and clear of the faces with another: for a pane's edge, its edge and the pocket's wall, between its two faces. It reads the parts' own material in the box: as a box is convex, the least distance between that is the least between their surfaces in it, never a section or a copy. On a STEP pair the verdict reads OCCT's exact distance between the parts cut by the box, and the second method Manifold's, between the meshes cut by it, within the chords on both; on an STL pair the mesh is the verdict, and points sampled on it the second method.
- **`--facing NAME=DIR`** reads, on a STEP pair, the least gap between faces whose outward normal stays within 60° of DIR all over, one of `+x -x +y -y +z -z`, and the other part's faces facing back, both ways round: DIR and its opposite read alike, as a gap has a face on each side. A rounded corner turns through 90° and faces neither way. Its second method samples points on those faces. An STL has no faces of its own, so it's refused there, saying to use `--box`.
- **Each place gives** `numbers.pairs.N.places.NAME`: `gap_mm` and `gap_by`, `gap_second_mm`, the points `from` and `to` it's between, and its `verdict`, so a need names `pairs.0.places.edge.gap_mm`. `numbers.places.NAME` says what each place is. `needs` refuses a place its command doesn't name.
- **With a place named, `--min-gap` and `--max-gap` hold each place's gap,** not the pair's least: a range is the play at one place, and a mated pair has several. The pair's least gap is read and said as before, and its overlap and its methods' agreement still count. The answer's verdict is the worst of the pairs' and the places'.
- **A box that catches no surface of one of the pair** says which lies outside it and which fills it with material, `NOT CAUGHT`, with no figure; one that catches neither part of any pair is `NO ANSWER`. A box round a contact reads 0, `TOUCHING`, as the pair does. On the overall least gap and `--lift`, nothing changes.
- **Planted** (`places/`): a pane 20 x 14 rounded 3 mm, 1.2 mm thick, in a pocket 0.25 mm wider round its edge and 0.15 mm over each face. A box round its edge reads 0.25, round the lip over a face 0.15, round a rounded corner 0.25, facing +z 0.15 and +x 0.25, OCCT and the mesh agreeing within 0.004 mm; with `--min-gap 0.25 --max-gap 0.25` the edge is `CLEAR` and the face `TOO CLOSE`, and at 0.2501 the edge is `TOO CLOSE`. As STLs, the edge and the corner read 0.25 by the mesh. A plate seated on a base between two arms 0.3 mm off its sides reads 0.3 in a box round an arm, the pair `TOUCHING`. With the fake model, a need on the edge's place passes at `done` at 0.25 and fails at 0.2501.

**A figure at its limit** (mqucifer/print-shop#72). On `eval-fit-3` `pause` said "0.400 mm above the pane at the pause, over 0.4 mm", and failed: the room was 0.4 by the file's figures and 0.40000000000000036 by the floats that add up the layers. `clearance` held its limits to a millionth of a millimetre, `pause` to nothing, and a need compared a figure the reply had rounded to four places. Now one rule holds every limit on the bench and every need's `at_least` and `at_most` (`bench/limits.py`):
- **A figure equal to its limit, to arithmetic's noise, passes.** Arithmetic's noise is `ARITHMETIC`, 1e-6 in the limit's unit, said once. It's a constant, not a band: no limit is loosened past it. Each comparison is `limits.under` or `limits.over`: `clearance`'s and each place's gap range, `pause --max-gap` and `--min-room`, `thin`'s nozzle and layer, `--min-body`, `light --min-open`, `thickness --max` and `--min`, `wall --min-wall`, `edges --min-radius`, `capture`'s lip and rim and share, `panes --min-area`, `layout --min-width`, `readback --min-share` and `--expect-delta`'s `--tol`, and `rays --d`'s and `--depth`'s `--tol`.
- **The figure a limit judges is the figure saved,** unrounded: `gap_mm`, `room_over_pane_mm`, `open_pct`, `least_wall_mm`, the least radii, `thickest_mm` and `thinnest_mm`, `width_mm`, `across_mm`'s ends, `floor_mm.min` and `change_mm3`. A need on it reads what the bench judged. The lines round them for print.
- **A figure said beside its limit** has as many places as it takes to tell it from the limit, so a reply never says a figure over its limit with the limit's own digits: "0.4001 mm above the pane at the pause, over 0.4 mm. Raise the pocket's floor by at least 0.0001 mm".
- **A reading's own error stays as it was,** each stated with its source, never widened, and held through the same rule (the operator's answer on mqucifer/print-shop#72): `wall --min-wall` 2 × the fine mesh's chord, 0.004 mm, as the sections are on the mesh; `edges --min-radius` 0.5% of R or 0.005 mm, OCCT's curvature on a spline; `thickness --max` and `--min` 0.004 mm, the chords; `capture`'s rim 0.01 mm and share 0.5 points, the chords on both outlines. A figure that passes only within one says so: "the 2.004 mm asked for, within the mesh's 0.004 mm". Reading these three against an exact figure, as `clearance` does, is for a later batch.
- **`thin` read a wall exactly the nozzle's width as thin:** its rays started 1e-5 mm inside the surface and didn't add that back, and the sections were opened by the nozzle's full width. A wall 0.4 mm wide at a 0.4 mm nozzle was `DISAGREE`; now it's `OK`, and 0.4001 `FAIL`.
- **Planted:** `frame.step` with a 1.6 mm pane has the room fit-3 had, 0.40000000000000036: `--max-gap 0.4 --min-room 0.4` is `OK`, where it was `FAIL`; 1.5999 is 0.4001 over and 1.6001 0.3999 under. Each other limit is run at its figure and just past it (`test_*_at_their_limit*`, `test_*_at_its_limit*`), and the before and after are in `~/print-shop/proofs/m18-gaps/`.

**`edges`** (mqucifer/print-shop#60) reads each outside edge of a STEP part: the Sponsor wants a case's edges, corners and lid softened, and nothing read an edge.
- **An edge** is read at points along it, every 2 mm, at least 3 and at most 25: the angle its two faces' normals turn through. Under 1° it's smooth, where a rounding meets a face. Over it, it's sharp, and outside if a point a little way into each face, and then between the two, is in the part; otherwise it's an inside corner, and isn't read. A chamfer's two edges are sharp, each turning 45°.
- **A rounded edge** is a curved face that meets a neighbour smoothly, a fillet or a corner where fillets meet, whatever it was built as. Its radius is the least it bends through convexly, read on a 9 by 9 grid over the face. A sharp edge is radius 0, so `least_radius_mm` is 0 where one is read, and `least_rounded_mm` is the least of the rounded ones, each with where.
- **Outside is what a finger reaches:** a ball 12 mm across, the test finger of IEC 60529 (IPXX-B) and IEC 61032 (test probe B), from outside every file named, and touching the edge from between its faces, not only flat-on to one. So the inside of a closed case isn't read when its lid is named, a seat flush with the lid isn't, nor the rim of a slot too narrow for a fingertip, and an edge round a plug's opening is. Each layer of every file is sliced onto a grid (0.25 mm, coarser past 8 million cells), Euclidean distance transforms find where a ball's centre fits and which of those places join the outside, and each place a ball touches an edge is held clear of every file by the mesh's exact distance. Every file named blocks the ball; one under `references/`, or named with `--with`, isn't read.
- **`--min-radius R`** fails a sharp edge or a rounding under R, naming each with where. A rounding drawn at R passes: it may read short by 0.5% of R or 0.005 mm. With no limit it's a reading, and passes.
- **A rounding stored as flat strips** reads as sharp edges, each turning a few degrees: one under 20° is counted in `faceted_edges`, and the reply says to build it with `fillet` or an arc. Rounded 3 mm as 16 strips a corner, a slab reads 68 such edges and no rounded face.
- **Second checks:** at each sharp edge read (150 at most, spread over them), the fine mesh cut by a plane square to it, and the angle its outline turns through at the edge, within 1° and each chord's lean; at each rounded face's least radius, the mesh cut along the direction it bends most, and a circle fitted to the outline's points on that face within half the radius, within 0.02 mm and 3% of it; and the ball's centre the grid found for each touch point, held clear by the mesh's distance. That the centre got there from outside is the grid's alone.
- **By group and by place** (mqucifer/print-shop#65). On `eval-edges-1` the need on the four upright corners read `rounded.19.radius_mm`, the 20th rounding in a list sorted by radius, which a rebuild can reorder, and three long calls went on picking corners out of the list. Each sharp edge and rounding read is now in one group, in the file's axes: `upright` where it runs within 30° of z (a rounding's way is square to its normal and to where it bends most); else `top` or `bottom` where its outward direction, the mean of its faces' normals, is more than 20° above or below level; and `side` for the rest. A rounding that faces up or down is a top's or a bottom's whichever way it runs, as a ball's corner bends alike both ways. `numbers.groups.NAME` has each group's counts, its least radius (0 with a sharp edge in it, none with nothing), where and on which file, and a need names `groups.upright.least_radius_mm`. `--box NAME=X0,Y0,Z0,X1,Y1,Z1` takes the edges with any point read inside the box, said at a point inside it, and `--facing NAME=DIR` those facing within 60° of one of `+x -x +y -y +z -z`, the edges round the face that faces it, each as `numbers.selected.NAME`. A rounding's radius is its own least, wherever on it that is, so a box never reads one looser than it is. Each group's and selection's least is among those the second method checks, past the 150 spread over the rest. An opening's edges in a side wall are grouped by the way they face (its top edge faces down, so `bottom`): read them with `--box`. On `mixed`, upright reads 3 mm, top 1.5, bottom 0 with its 8 sharp edges, and side none.
- **Planted:** a block rounded 2 mm all over (`OK` at 2, `FAIL` at 2.1); one with its bottom left sharp (8 sharp edges, all at its foot); an open tray (16 sharp edges a finger meets, 12 inside corners not read), the same tray with its lid flush on it (none), and with the lid as a reference (none, the lid not read). On a case 100 by 70 by 35 mm with 30 vent slots, a grille of holes, four bosses and a plug's opening, it takes 9 to 11 s: the opening's 4 edges are read, and the slots' and holes' rims are flat-on.

**`rays` from a point in air** (mqucifer/print-shop#65). On `eval-edges-1` rays from a rounded corner's centre, which lay in the box's hollow, read `across` 5.66 to 53.92 mm, and it took three long calls to see that wasn't the corner's radius. Where the centre is in air, each level now gives `nearest_wall_mm`, the nearest wall any ray meets, and a note says what `across` is: the open space's width through the point, from the wall one ray meets to the wall the opposite ray meets, a hole's diameter on its axis, and never an outside corner's radius, whose centre is always inside the part, in its material or its hollow, with `edges` to read it. From the tray's corner centre, 1 mm from two inside walls, the nearest wall reads 1.0 and the least across 2√2.

**`wall`** answers what `thin`'s `thinnest_flat_mm` was quoted for on `cup-1`: the hanging hole's wall. Any point inside the hole names it, and it reads the hole's whole length. The sections take the least distance from the hole's edge to any other edge of the material round it. The rays never touch a section, and meet them where the wall is least, as the least wall runs square to the hole's wall. Between two corners it isn't square to either, rays read it thicker, and that's `DISAGREE`, said why. Material beyond the hole's ends isn't counted. `least_wall_mm` is the number a need limits, or `--min-wall`, which holds a wall drawn at the limit within the mesh's chords.

**A close-up** draws R mm all round a point along a view (`top` unless named), so a fine motif or a 3 mm hole can be judged: at 512 px and `R` of 4 that's 64 px per mm, where the first real run's 3 mm holes were 27 px. It looks along the view and doesn't cut anything, so what's inside a part needs `--section`. Nothing of the parts in the window is a `FAIL`, so one aimed wrongly doesn't read as a picture.

**A test piece** is drawn see-through in grey, and each picture says it isn't the part. It's whatever the one asking says it is, as nothing can tell by looking. So a script writes test pieces to files of their own, and a piece inside the part's file is drawn as the part.

**`capture`** answers whether the frame's shape holds each pane. It's how the Sponsor prints them, like a lens in a pair of sunglasses without the snap: a pane is set in at a pause and printed over to lock it in, not to bond it. So nothing here reads a material or counts on adhesion, and the frame's material is free. For each face of each pane:
- **Can it slide out?** The pane is read at every place its play lets it sit, against everything beyond the pocket, by polygons and then as a solid swept out. Passing at any of them is `FAIL`, so a pane held only while it's centred isn't held.
- **Can it swing out?** A lip that lies all to one side of the pane's centre is `FAIL`, as it can pivot about that lip.
- **How much lip?** `least_lip_mm` is the narrowest round the edge, and `least_lip_with_play_mm` what's left once the pane has moved away from it. Under `--min-lip` after its play (0.4 mm, a nozzle's width, unless you say) is `FAIL`, with how much of the edge and where.
- **How thick?** A lip under a layer at its root is `FAIL`, and `air_mm` is how far the pane can rattle before it reaches it.
- **Edge with no lip** is reported and not judged, as in `panes`, if the rest goes round. Where a lip stops it falls away to nothing round a window's corner, which isn't counted as thin, and one that tapers over a long way is.
- **Why it isn't held** (mqucifer/print-shop#46). On `eval-tip-1` the pocket's cut ran on through the top face, and `capture` said only that the pane comes out, with no lip along all 59.3 mm of its edge. The model's own 2D check said the lip was there, it judged the bench wrong, and it spent about 1.5 hours and four calls of 21k–40k tokens' reasoning that ended without a tool call. Now a face that comes out, or holds the pane by less than the limit along half its edge or more, says what the frame has beyond that face, stretch by stretch, with where on the edge and the heights it read. It reads every section beyond the pane's face as one, along the line square to the pane's edge at each spot, and says one of:
  - the frame covers the pane by only so much, where the limit after play needs more;
  - nothing covers the edge, and the frame over the pane starts so far in from it;
  - the hole is as wide as the pocket, to 0.03 mm, so nothing overhangs the pane on that face and the pocket's cut may run through the face;
  - the hole is so much wider than the pocket, or narrower but stopping short of the pane, and the frame starts so far out from the pane's edge;
  - there's no frame within 10 mm, or nothing of the frame beyond the pane's face at all, with the pane's face and the frame's end.

  The pocket's wall is read on the same line, from the opening at `--pocket-z`. Frame met across a pane counts as over a spot only if it's no nearer the pane's edge anywhere else, so the far edge's lip isn't read as this one's. Each kind is said once, with how much of the edge it runs along, in how many stretches, where the longest runs, and the range of its figures. A single spot (a lip's falling end, a corner) isn't said, and every stretch is in each face's `over`. **Second check:** at a spot in each stretch, rays straight beyond the face, walked along the same line, and the pocket's wall by a level ray at `--pocket-z`. A different kind, or a figure more than 0.04 mm off, is `DISAGREE`. Rebuilt from `eval-tip-1`'s frame with its pocket cut through the top again, the reply is the run's own at call 87, then "Over it, the frame read from z=2.5 to its top at z=4: all round its edge, 59.3 mm, the hole is as wide as the pocket" (`~/print-shop/proofs/m18-why/`).

**A rim sized to the visible share** (mqucifer/print-shop#37, criterion 6). On `suncatcher-2` the Sponsor ruled 1.2 mm for big panes and 0.55 mm for small ones, before play, and a need could only give one `--min-lip` for all, so nothing held the big panes at 1.2 mm. "Small" by name or by eye can't be checked: the Sponsor, 2026-11-04, it has to be a math check, not a matter of knowing. `--full-rim R --least-rim R2 --min-visible P` take the request's full rim and smallest rim, before play, from the pocket's wall to the opening's edge, and its least share of each pane visible. All three go together, with no default, and not with `--min-lip`.
- **The rim each pane needs:** the full rim if P% of the pane stays visible with it; if not, the widest rim that keeps P%, by insetting the pane's outline (true distance, round joins) by the rim less the play and bisecting; and if even the smallest rim can't keep P%, none, and the pane is to be removed. A long thin pane is judged by how much its rims cover: its width counts and its length doesn't.
- **The check:** the pane's lip, read per spot as for `--min-lip`, is at least the rim it needs all round, and its visible share on the frame as built, covered on neither face, is at least P%. The visible share is `light`'s own reading (`glass.visible`), one function for both.
- **Tolerances:** the lip may fall 0.01 mm short of the rim it needs, the mesh's chords on both edges, and the share 0.5 percentage points short. A rim drawn exactly at the need leaves exactly the share, so the share's tolerance is the same chords read as area.
- **What it says:** each pane's share, the share wanted, the rim it needs and the rim it has, and how that rim was chosen, in three figures (mqucifer/print-shop#61): the full rim, the share it leaves visible, and the smaller rim that keeps the share wanted, or that even the smallest rim doesn't. On `suncatcher-3` the reply gave the rim to set and not how, and two calls of long reasoning rebuilt the logic. `rim.chosen` is `full`, `smaller` or `remove`. A failing pane says "set this pane's rim to X mm before play", with where it's short, or "remove this pane", or, where its rim is right and too little shows, that the frame covers it elsewhere.
- **The rim to set is the rim needed, rounded down to 0.001 mm,** so a cell built at it passes in one step: rounded down, the share stays at least the one wanted, and the lip falls short of the need by under 0.001 mm, inside its tolerance. Rounded to 0.01 mm, a 2.71 mm pane needing 0.5554 mm would be told 0.56, which leaves 59.48% visible, and be told 0.56 again. On `suncatcher-2`'s ask-2 frame rebuilt with the skill's mitred offsets at each figure the reply gave, every pane passes at the next `capture` (`~/print-shop/proofs/m18-verify/one-step-ask2/`).
- **Second checks:** the share by rays straight up through the frame from a grid in the pane, and the share at the rim needed by a grid of points at least that far from the pane's edge.
- **Which way the rim moves** (mqucifer/print-shop#65). On `eval-rims-4` the longest call, 31 minutes and 85,000 characters of reasoning, went on "its rim needs 1.2 mm before play, and has 1.0 mm at the least", working out which way a larger rim moves the visible share. Each pane's line now says what to change and what it leaves: "Widen its rim by 0.2 mm, from 1 to 1.2 mm before play: the opening's edge moves 0.2 mm in, over the pane, which covers more of it, and leaves 81.46% of it visible", or "Narrow its rim by 0.131 mm, from 1 to 0.869 mm before play: the opening's edge moves 0.131 mm out, off the pane, which shows more of it, and leaves 60.00% of it visible", then whether a wider rim passes too (a full rim: any rim at least it, while the share stays) or none does (a smaller rim: wider leaves too little visible, and narrower is under the rim it needs). A rim already right says "leave it". A failing pane's verdict says the same. `rims/both-at-1`, both panes at 1.0 mm as on `eval-rims-4`, reads those words (`~/print-shop/proofs/m18-bench/replies/`).
- **Back-tested** on `suncatcher-2`'s ask-2 frame at 1.2 mm, 0.55 mm and 60%, against the operator's own inset of each pane file: the rim needed agrees to 0.001 mm and the share at the full rim to 0.00 points. The big panes need 1.2 mm, the legs 0.78, the triangles 0.86 and L1 and R1 0.99, and none is removed (`~/print-shop/proofs/m18-verify/share-ask2/`).
- **Rims and lips:** a rim is a lip before play, from the pocket's wall. `least_lip_mm` is the lip after play, how far it covers the pane in the middle of its pocket. `--min-lip` takes the play off once more, for a pane slid to one side, as it always has, and keeps its 0.4 mm when given alone.

A pane too thick for its pocket is `FAIL`, as is a height that misses the pane. It doesn't read a pane forced past a lip that bends. Pair it with `pause`, which says when the pane goes in and whether the nozzle clears it.

## Never take a tool's word

The map's table, row by row. Each row that touches these commands is a planted case in `tests/test_bench.py`, named after it.

| What we saw | What the tool said | Here |
|---|---|---|
| Near-touching faces: results empty or disagreeing | Often zero overlap | `clearance`: 66 cases rerun on our own hinge, and a pair where OCCT reads zero is `DISAGREE` |
| A pocket that missed the body | Feature valid | `readback` is `NO CHANGE`, and `rays` finds the centre in material |
| A bearing seat mostly in mid-air | No error, watertight, one body | `rays` counts the rays that hit nothing, and `readback --cutter` the share of the cutter in the body |
| Mesh repair that kept 5% of the volume | "Watertight" | `readback` fails it, stated or not |
| Thin shelled surface: CAD volume swung, even negative | A plain number | `info` is `NO ANSWER` or `DISAGREE`, and names OCCT's number |
| A parameter that drives only part of a design | Everything healthy | `params` names which pieces moved |
| Four-bar, nothing grounded, clevis assemblies | Success, or rc -1 | Motion: not in this bench |
| Peak stress at a corner, contact with a missing constraint | A plain number, 0.0 MPa | Stress: not in this bench |

The Sponsor's way of printing panes adds three, each a planted case:

| What could go wrong | What would look right | Here |
|---|---|---|
| A pane standing above the next layer, where the nozzle hits it | The layer count alone | `pause` is `FAIL`, by both methods' layer, among several openings, and on the plate. `nozzle_over_pane_mm` is how far the tip clears it |
| A lip narrower than the pane's play | A lip in the section at one height | `capture` moves the pane by its play, and it comes out |
| A lip down one side | A lip, and no way to slide out | `capture` is `FAIL`: it can swing out |
| A pocket cut on through the top face (`eval-tip-1`) | A 2D check of the pocket and the window, which shows a lip | `capture` says the hole over the pane is the pocket's own outline, all round, by sections and by rays |
| A pane with a hole round an island of frame (`cup-1`) | "Too thick for its pocket", a ceiling mid-pocket, a section with no walls | `capture` holds it by its lips round every ring, `pause` agrees by both methods, and the section draws the island |
| A pane number taken for a file's (`cup-1`) | `pane 1` | each pane is said with where it is, and its file |
| A hole's wall quoted from the whole part's thinnest flat (`cup-1`) | `thinnest_flat_mm` 2.0 | `wall` reads that hole, and `FAIL`s under `--min-wall` |

Building this found more, each now handled and said in the code:
- **CadQuery's `tessellate` tolerance is relative,** a share of each edge's size, not the mm it looks like. On a real part that read as a 0.03 mm false gap. The bench meshes with absolute tolerances, through OCCT directly.
- **Manifold's `RayHit.distance` is a fraction of the ray,** not a length.
- **OCCT's adaptive volume moves with its accuracy setting** on a real file by far more than its own error estimate, so the bench reads its default, and checks it against the mesh.
- **A coarser mesh isn't always further from the truth,** so how far a figure can rest on the chords comes from the chord tolerance times the curved surface's area.

A second check has to ask the same question as the first, or it only makes noise. Running over our 51 reference parts showed that: rays along a surface's normal read a cone or a thread thinner than it prints, and the top of a cylinder on its side as thin when no layer prints it. So a wall's ray runs level, across the layer, and shallow slopes aren't read as walls. A sharp point, a feather edge, a cusp and a few stray rays are noted with where they are, and don't fail a part.

## Limits

- **Docker's disk is shared,** with LiteLLM's database, crew's workspaces and any running tick, and it filled on 2026-11-01. There's one image, `print-shop/bench:0.9`, of at most 4 GB. It holds what 0.2 did, with the bench's version as a label: the bench code is mounted, so 0.3 marks the bench that reads islands and holes (mqucifer/print-shop#27), 0.4 the one with `light` and `thickness` (mqucifer/print-shop#37), 0.5 the `capture` that says what the frame lacks over or under a pane (mqucifer/print-shop#46), 0.6 the `info` that reads small flat faces, the `capture` that names other plays and the sheet that marks files by name (mqucifer/print-shop#54), 0.7 the enclosure's `edges` and `clearance --max-gap` (mqucifer/print-shop#60), the needs that follow the part's files and the check for curves stored as strips (mqucifer/print-shop#59), and `layout` and `capture`'s rim figures (mqucifer/print-shop#61), 0.8 `clearance --lift` and its verdict on OCCT's exact gap, `edges` by group and by place, and `capture`'s and `rays`' clearer replies (mqucifer/print-shop#65), and the refinement pass's turn onto the side the run names and its reading of gap fill inside a wall (mqucifer/print-shop#66), 0.9 `clearance`'s gaps by place and one rule for a figure at its limit (mqucifer/print-shop#72), and each shares all of 0.2's layers (0.1 had no `lookup` or `docs` indexes; any of them may still be on a machine). `build` refuses if that could leave under 5 GB free, and `check` says if the image or the disk is over. Its first layers are mqucifer/model-performance's CadQuery image, so where that's present it costs tens of MB.
- **A container** has no network, 2 CPUs, 3 GiB with no swap, a read-only image, 1 GB of `/tmp`, the invoking user, no capabilities, no log on Docker's disk, a 2 GiB limit on any file, and 600 s. `/work` is the only thing it writes, and the bench's code is mounted read-only, so changing the code never costs another image. Every package is pinned.
- **It moves to another machine** by clone and `build`: CI builds it for amd64 and runs the planted cases there, and the Mac builds it for arm64.
- **Accuracy:** the mesh is at 0.002 mm, and a figure is good to the band it prints. Nothing here has been compared with a print. A pause layer assumes a layer takes its outline from its mid-height. Orca has since agreed with it on our fixtures and on three approved runs (the refinement pass, mqucifer/print-shop#51), except at a tie: a ceiling on a layer's mid-height, where `pause` closes the pocket a layer early and Orca leaves it open. The Centauri's mid-print pause hasn't been run.
- **`bench/refine.py`** isn't a command: it's the refinement pass's geometry, started by the harness. It meshes STEP for Orca at Orca's own GUI defaults and holds the mesh to OCCT, and reads Orca's lines against the part.

## Tests

Planted fixtures are made from scratch by `tests/bench_cases/make_fixtures.py`, with right answers from arithmetic: `uv run pytest -q -m bench`. No Sponsor's design, or anything derived from one, is in this repository, and `scripts/bench_local_run.py` refuses to write inside it. `tests/test_bench_local.py` (`-m bench_local`) runs on the Sponsor's exported frame where it's present, and skips elsewhere. The frame's heights and play are in `~/print-shop/bench-local.json` on the Mac, off this repository. `scripts/bench_local_run.py triforce --out DIR` saves that run's figures to a folder off the repository, and `reference --out DIR` runs the commands over our reference parts in mqucifer/model-performance.
